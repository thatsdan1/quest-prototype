QUEST PROJECT — TEAM REVIEW PACKAGE
===================================

QUICK START — NO INSTALLATION NEEDED

1. Download and unzip "QUEST Prototype.zip".
   If downloading from GitHub, sign in with collaborator access, choose
   "Code" -> "Download ZIP", and unzip that download instead.
   Windows: right-click the ZIP and choose "Extract All".
   Mac: double-click the ZIP.

2. Open the extracted folder: "QUEST Prototype" for the team package,
   or "quest-prototype-main" for a GitHub download.

3. Double-click "QUEST Prototype.html".
   If it opens as text, right-click it, choose "Open With", and select
   a current web browser such as Chrome, Edge, Firefox, or Safari.

4. The production board opens with fictional sample jobs.
   No Codex account, sign-in, internet connection, Node.js, or Python
   installation is required for this method.

Open the HTML file after extracting the ZIP; do not run it inside an
email preview or the ZIP viewer. You can also send just the standalone
"QUEST Prototype.html" to someone who only needs to try the app.

WHAT TO TRY — A FIVE-MINUTE WALKTHROUGH

0. Quick tour (one minute)
   The first time you open the board, a card in the corner offers a
   tour. Choose "Take the tour" or "Not now". The ? button at the top
   of the screen starts it again any time. Use Next / Back, the arrow
   keys, or Esc to leave.

1. Weekly assemblies (the opening view)
   Click a day to review the 30 cells in use. Darker green means more of a
   unit's standard hours are complete. Each cell has "New job"; each unit
   has "Continue next shift". Days after today show as Upcoming.

   Which button?
   - New job: a unit that isn't on the board yet. The button at the top
     asks for the cell; the one on a cell fills it in. Same form.
   - Continue next shift: the same unit, picked up by the next shift.
     Start is where the last shift stopped. Use it instead of a new job.
   - Next unit this shift: the same people finished a unit and start
     another one today, with the hours they have left.
   - Edit (or click the unit): fix or update a shift already saved.

2. Daily goals
   Select Daily goals. Each card leads with its cell and shows Start, Goal,
   and Stop by step name. Finished shifts use the workbook colours:
   red, yellow, green, purple. The key sits above the cards.

3. New job: the same fields as one block of the Excel board
   Select New job at the top or on a cell. Cell, date, and shift
   come from where you clicked; use Change to adjust them. Enter:

     Name(s):   Demo Operator
     Job #:     TEAM-DEMO-01
     Hand:      LH
     Part:      A320 inner bondment
     Start:     5 · Peel & prep skin

   The calculated goal should be step 13, "3rd debulk".
   Set "Additional hours worked" to 1: the goal becomes
   step 14, "Lay up ply level 6".
   Set Stop to "13 · 3rd debulk", add a comment, and save.
   The card should show a shift gap of -1 step.

   If you changed the sample route in Process setup, the result may differ.
   Use a unique job number when repeating this exercise for the same shift.

4. End-of-shift colour
   Update that job and tick "Assignment finished". It earned 8.0 standard
   hours against a 9-hour budget (8 h + 1 h overtime), so it turns
   "Yellow · 8.0 h". Without the overtime hour it would be green.

5. Shift handoff and history
   Choose Next shift on your new job and enter a different demo operator.
   Start carries forward as "14 · Lay up ply level 6"; save the new shift.
   Choose History on the card to verify both names are still recorded.
   Production-day order is 3, 1, 2; Shift 2 rolls into the next day.

6. Supervisor review
   Open Supervisor review in the sidebar. It counts red, yellow, green,
   and purple shifts per operator over 1, 2, or 4 weeks and flags repeats.
   Click a purple shift to open that job's history. This page has no
   login in the prototype, and what purple means is still to be confirmed.

7. Process setup
   Inspect the named route, shift budget, goal rule, and colour bands.
   "Paste a route from a spreadsheet" accepts lines like "Peel skin, 60"
   or two columns copied from Excel. "Restore standard route" reloads the
   sample route. Saving creates a new revision; existing records keep theirs.

8. History, TV, insights, architecture
   Shift history lists every update; Export CSV sends the selected records.
   TV display shows start, goal, stop, gap, and hours in large type; long
   lists rotate every 20 seconds and Escape exits. Insights and
   Architecture explain goal attainment and the proposed system.

NEW IN V6: STATION ALERTS

- The bell in the top bar counts stations that need attention today.
  Click it (or Station alerts in the sidebar). Cell 04 is blocked and
  Cell 02 is at risk.
- Go back one day: Cell 05 waited 1.5 h on tooling, a process efficiency
  of 81%. It is critical because it keeps happening at that station.
  Choose Acknowledge.
- Open TV display: a banner lists the stations still needing attention
  and their cells are outlined. Acknowledged stations drop off.
- Alerts follow the process, not the person. Process efficiency =
  1 - waiting / total hours. Save a job with 3 h waiting in an 11 h day
  (8 h + 3 h additional): the message says the station is at 73%.
  The operator's person grade = standard hours completed /
  (total hours - waiting), so the wait is not held against them.
- Alert rules (bottom of the page) set the warning and critical lines
  (90% and 75%) and how many in a row escalate.

NEW IN V6: OPERATIONS HOURS, PEOPLE AND UNITS

- Open Operator day. Operations sets the standard day (8 h). Leads add
  training-center time there when it happens; it fills the person's
  day without touching any unit.
- Go back one day. Each person has a bar: green building, amber waiting,
  blue training, grey time not booked to any unit. Jordan Lee spent 2 h
  in the training center. Harper Moss, a trainer, has 8 h of training
  on the floor.
- On the board, choose New job. Set "Additional hours worked" to 4:
  the goal covers 12 h. In the Waiting box enter 2.5 hours waiting for
  "Tooling / fixture". The goal line reads
  8.0 h regular + 4.0 h additional - 2.5 h waiting = 9.5 h to build.
  The wait is not held against the operator: stop at the goal, finish,
  and save, and the shift is green. The station still alerts as
  Waiting. No approval step; the comment holds the reason.
- Two names on a job share one plan; they do not double it.
- Open Insights in week view:
    Why units wait . 80/20  - waiting hours by reason, the top reasons
                              highlighted; open one to see its units.
    Units                   - time-study hours earned vs. hours to
                              build and waiting, for each whole unit.
    People                  - each day (8 h + additional) vs. booked
                              hours. Show "Worked additional hours" to
                              check those days against standard hours
                              earned.
- Open any unit's history for its whole-unit totals.
- Hours are lead-entered; no time clock or Kronos connection is involved.

CORRECT MISTAKES

Use Edit on the weekly unit or Update job on a daily card. Job number,
name, cell, date and shift can be corrected; earlier values remain in
Shift history. Renaming a unit keeps its assignments linked.
Use Remove to choose the whole unit or one assignment. Removed jobs in
the sidebar provides Restore. Removing the latest assignment alone may
reveal earlier recorded progress. Reset demo is a separate destructive action.

TV DISPLAY

Open TV display from Weekly assemblies for the cell grid: every cell in
use on one screen, in rows of six. Active cells are shaded by completion,
idle cells (a unit, but no work recorded today) are greyed, and open cells
are dashed. The bar on top shows line health and any station alerts.
Display also offers Line timeline (where each unit sits in its route) and
Operator goals. Individual results show as colours, not numbers.
Per screen (all, 18, 12, or 6 cells) and Rotate (10-60 seconds) change
the layout for every TV; so does Process setup -> Floor display, which
also sets how many cells are in use (30 now, up to 36). Escape or Exit TV
display returns to the board.
Opened as a file, the TV shows only this browser's data. For a TV that
follows the leads' entries live, use the board server below.

YOUR DATA AND YOUR TEAM'S DATA

- The package starts with built-in fictional sample records and timings.
  It does not contain edits made in someone else's browser.
- Changes are saved in the browser on your device when storage is available.
  Teammates do not see one another's changes automatically.
- Opening the file in another browser or moving it to a different location
  may create a separate local dataset. The file version and local-server
  version also have separate storage.
- Export CSV from Shift history to share the selected records. CSV is a
  history report, not a full backup of process settings or an import file.
- Clearing browser storage or using Reset demo data removes local edits.
  Reset demo data also restores the sample timing configuration.
- All production data, step names, and timings are fictional. A route pasted
  into Process setup stays in your browser. SAP, MPP, SharePoint, and
  other ST systems are not connected. The architecture is a hypothesis.

OPTIONAL — SHARED BOARD SERVER FOR TVs AND LEAD PCs

The board server lets every screen share one board: a lead saves on a PC
and the floor TV updates within a second. It needs Node.js 18 or later
(nodejs.org); nothing else is installed.

  In a terminal in the project folder (see below for how to open one):

  npm start

  Then open http://127.0.0.1:4173 on this computer.

  To share with other devices on the network:
    Mac / Linux:  HOST=0.0.0.0 npm start
    Windows:      set "HOST=0.0.0.0" && npm start
  Open http://<this computer's address>:4173 on each lead PC, and
  http://<this computer's address>:4173/?display=tv on each TV.
  The board is saved in the "data" folder next to the app.

The first screen that connects to a new server seeds it with its own
board. Reset demo data on any screen resets the board for every screen.

OPTIONAL — RUN THROUGH A LOCAL SERVER

Use this if your browser restricts saving from a directly opened HTML file,
or if you want to edit and test the source files. Python 3 is required for
this optional method only.

MAC / LINUX
  Open Terminal, type "cd " (with a space), drag the extracted
  project folder into Terminal, and press Enter.
  Then run:

  python3 -m http.server 4173 --bind 127.0.0.1 --directory dist

WINDOWS
  Open the extracted folder in File Explorer. Click the address bar,
  type "cmd", and press Enter. In the command window, run:

  py -m http.server 4173 --bind 127.0.0.1 --directory dist

  If the Python launcher "py" is unavailable but Python 3 is installed,
  use "python" instead of "py".

BOTH
  Keep the terminal window open and visit:

  http://127.0.0.1:4173/

  Press Ctrl+C in the terminal when finished.
  If port 4173 is already in use, replace it with 4174 in both the command
  and the browser address.

  This address works only on the computer running the server. It is not
  a team-sharing link. Send the ZIP or HTML file for independent review.

TROUBLESHOOTING

- The page displays source code: open the HTML file with a web browser.
- The board is empty: check the date and filters. Select A320 inner bondment,
  all work cells, and an appropriate shift. The second sample process may
  have no assignments until you add one.
- No jobs today: saved examples may belong to an earlier date. The app
  initially opens the latest saved assignment date when today is empty.
- A change did not save: check for an error under the form, such as an end
  step outside the sequence or a duplicate job/date/shift assignment.
- Changes disappear: check the storage status, avoid private browsing for
  repeatable demos, or use the optional local-server method.
- The localhost page cannot be reached: start the server on your own
  computer first, or use the standalone HTML file instead.
